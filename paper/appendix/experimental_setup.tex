\paragraph{Environment.}
Dependencies are managed with \texttt{pixi} and locked in \texttt{pixi.lock}, so the software environment is reproducible from the lockfile rather than from a loose requirements list. Two environments are used. The \emph{default} environment contains BDF and its core dependencies; the \emph{benchmark} environment additionally carries the heavier baseline libraries (LightGBM, CatBoost, NGBoost, XGBoostLSS, and the \texttt{rpy2} bridge to the R \texttt{drf} package), which are isolated because several of them impose mutually incompatible pins. Commands below are annotated with \texttt{-e benchmark} where that environment is required. The performance-critical split-search kernels are Rust extensions built through \texttt{maturin}; \texttt{pixi run setup} installs dependencies, builds the extension, and installs pre-commit hooks in one step.

\paragraph{Protocol lock.}
Real-data experiments use seed $1234$ with ten shuffled folds (\texttt{KFold} for regression, \texttt{StratifiedKFold} for classification); the main synthetic study uses seed $42$ with the same fold convention. Split 0 supplies the training/validation pair for tuning; splits 1--9 supply refits and evaluation scores at the selected hyperparameters. The shared observations and inferential scope of this convention are specified in Appendix~\ref{app:benchmark-protocol}. Every result YAML records the invoking command, the git commit and dirty flag, the seed, the fold count, the tuning metric, the resolved model configuration, the selected hyperparameters, the per-fold metrics, and the dataset metadata, so each reported number is traceable to the run that produced it.

\subsection{Models}\label{app:experimental-setup-models}

\subsubsection{Regression Models}\label{app:experimental-setup-reg-models}
The regression benchmark compares BDF leaf families against probabilistic and calibrated tabular baselines. The locked BDF-Full regression aggregate selects among Normal--Normal, Student-$t$, KDE, and Gamma--Poisson leaves where compatible with the target domain; other implemented leaves are exploratory unless listed in Table~\ref{tab:bdf-leaf-regimes}. The submitted aggregate includes Bayesian ridge regression~\citep{bishop2006pattern}, NGBoost~\citep{duan2020ngboost}, XGBoostLSS~\citep{marz2019xgboostlss}, CatBoost with uncertainty~\citep{dorogush2018catboost,malinin2021uncertainty}, conformalized LightGBM/random-forest baselines built on MAPIE~\citep{taquet2022mapie}, quantile-regression forests~\citep{meinshausen2006quantile}, distributional random forests~\citep{cevid2022distributional}, Gaussian deep ensembles~\citep{lakshminarayanan2017simple}, $k$NN-KDE, and a climatological reference model used for skill scores. Exact constructor settings and tuning ranges are specified in the YAML files under \texttt{benchmarks/configs/model/}; the result artifacts record the resolved configuration used for each run.

Distributional random forests and likelihood-based distributional regression forests are closely related approaches for estimating conditional distributions using trees. We include DRF through the R \texttt{drf} package via an isolated \texttt{rpy2} worker process, because the available Python package is deprecated. XGBoostLSS is evaluated as a fused distributional-boosting baseline: Gaussian, Student-$t$, Laplace, and Gaussian-mixture variants are run under the same fold protocol and the variant selected on fold-0 tuning CRPS is used for each dataset. Variants with incomplete evaluation folds are excluded from this fused selection for that dataset. The incomplete XGBoostLSS metric vectors are: Gaussian on \texttt{yacht\_hydrodynamics} (8/9 CRPS folds), Student-$t$ on \texttt{energy\_efficiency} (8/9), Student-$t$ on \texttt{parkinsons\_updrs} (8/9), and Student-$t$ on \texttt{yacht\_hydrodynamics} (6/9). Laplace and Gaussian-mixture XGBoostLSS completed all 15 datasets with 9/9 evaluation folds.

NGBoost is likewise evaluated as a fused baseline over Normal, Laplace, LogNormal, Exponential, and Poisson distributions, with target-domain metadata restricting positive and count families to compatible datasets. Eligibility requires 9/9 finite CRPS and RMSE folds. The LogNormal candidate is ineligible on \texttt{bike\_sharing} and \texttt{concrete\_strength} (8/9 CRPS folds and non-finite RMSE) and on \texttt{superconductor} (non-finite RMSE). The other NGBoost candidate/dataset pairs used in selection meet this completeness rule. The selected Exponential fit on \texttt{forest\_fires} is finite but catastrophically poor on held-out folds; it is retained rather than clipped or reclassified as a numerical failure. The Exponential family is eligible there because the processed target (log1p-transformed burned area) has domain \texttt{nonnegative\_real}, which the domain filter accepts for Exponential; eligibility is determined by target-domain compatibility, not by tuning-fold performance.

\subsubsection{Classification Models}\label{app:experimental-setup-clas-models}
The classification benchmark is binary. The submitted comparison includes BDF with Beta--Bernoulli leaves, random forests, LightGBM, NGBoost, calibrated random forests, calibrated LightGBM, and $k$-nearest-neighbor classification. All reported classification metrics are computed from predicted probabilities for the positive class. Multiclass BDF variants based on Dirichlet--multinomial leaves are implemented in the distribution library but are not empirically validated in this paper; all classification claims are restricted to the binary setting.

\subsubsection{BDF leaf families and score regimes}\label{app:bdf-leaf-regimes}
Table~\ref{tab:bdf-leaf-regimes} separates the leaf families used in the submitted benchmark from implemented exploratory variants. A BDF-Full candidate is eligible only on datasets whose target-domain metadata are compatible with the leaf family; the selected family and score regime are then chosen by the fold-0 protocol in Section~\ref{app:benchmark-protocol}.

\paragraph{Practical defaults.}
Two regression defaults are useful for different goals. The public \texttt{BDFRegressor} default is \texttt{NormalMuNormal} with automatic empirical-Bayes prior centering/scaling, which is the recommended general-purpose tradeoff because it keeps conjugate mean updates, stable density forecasts, and low operational complexity. When maximum regression benchmark performance is prioritized over exact Bayesian interpretation, the performance-oriented default is the Student-$t$ leaf with \texttt{score\_regime=nll\_bic}: it provides robust tails with a BIC-sized split regularizer, but remains a fitted-density/evidence-surrogate configuration rather than an exact marginal-likelihood model.

\subsection{Benchmark Protocol}\label{app:benchmark-protocol}
All real-data benchmarks use seed $1234$ and ten shuffled train/test splits. Let $\mathcal D=\bigsqcup_{j=0}^{9}\mathcal D_j$ denote their disjoint test blocks. For each model configuration, Optuna's TPE sampler \citep{akiba2019optuna} runs 50 trials, fitting on $\mathcal D\setminus\mathcal D_0$ and scoring on $\mathcal D_0$ using CRPS for regression or log-loss for classification \citep{gneiting2007strictly}. With $A_\lambda$ denoting a fit at hyperparameters $\lambda$, the protocol is
\[
\hat\lambda=\arg\min_{\lambda\in\Lambda_{\mathrm{tried}}}
L_{\mathcal D_0}\!\left(A_\lambda(\mathcal D\setminus\mathcal D_0)\right),
\qquad
\widehat R_j=L_{\mathcal D_j}\!\left(A_{\hat\lambda}(\mathcal D\setminus\mathcal D_j)\right),
\quad j=1,\ldots,9.
\]
Thus ``fold-0 tuning'' refers to a train/validation split, not tuning within the block $\mathcal D_0$. The selection objective is evaluated on $\mathcal D_0$, which is disjoint from every evaluation block, so no response scored in folds $1$--$9$ enters the tuning objective; $\hat\lambda$ nonetheless depends on those observations because they are part of the training set $\mathcal D\setminus\mathcal D_0$ of every tuning fit. This shared-tuning protocol limits search cost and retains 90\% of the observations for each fit, including on small datasets. It gives a common comparison protocol across methods, but the reported scores can carry selection bias and are not an independent or nested-CV estimate of the full tuning procedure. Tables report means and descriptive fold standard errors over the nine refits; these do not quantify variability from repeating hyperparameter selection, and the overlapping training sets make fold scores dependent.

For BDF, Optuna tunes prior-scale hyperparameters jointly with $(\alpha,\delta,\gamma)$, $n_{\text{trees}}$, $\text{max\_depth}$, and $\text{min\_samples\_leaf}$. Prior locations remain \texttt{auto} markers: every tuning or evaluation fit resolves them from its own training partition (e.g.~$\mu_0=\bar y_{\mathrm{train}}$). Evaluation holds the tuned scales fixed while recomputing these centers from $\mathcal D\setminus\mathcal D_j$.

The benchmark does not cap the number of training or test observations at 100 or 1000. Those constants refer to the number of predictive draws used by sample-based probabilistic metrics: during Optuna tuning, \texttt{tuning\_sample\_size}=100 predictive samples are drawn for CRPS to keep model selection affordable; during final evaluation, \texttt{sample\_size}=1000 predictive samples are drawn for CRPS, interval scores, coverage, and PIT diagnostics when a model exposes samples rather than analytic CDFs or quantiles. Methods with native quantile outputs, such as QRF, are evaluated on their quantile grid rather than by subsampling observations. Search spaces are defined in \texttt{benchmarks/configs/model/*.yaml}, and each result YAML records the resolved model configuration, dataset metadata, seed, fold count, tuning metric, tuning time, predictive-sample count, and fold-level metrics. New benchmark runs also record per-fold point and probabilistic prediction wall-clock times; the locked real-data YAMLs used for the current paper predate this instrumentation, so Table~\ref{tab:real-benchmark-timing} reports absolute fit/tune times and Table~\ref{tab:complexity} reports controlled prediction overhead.

Failed folds or mathematically undefined predictions are not silently imputed. The locked fused regression aggregates require nine finite CRPS and RMSE values for each candidate/dataset pair before choosing the lowest tuning score. This completeness condition makes family selection depend on evaluation outcomes as well as tuning performance. It changes the tuning-only winner from Gaussian to Laplace XGBoostLSS on \texttt{yacht\_hydrodynamics}, from LogNormal to Poisson NGBoost on \texttt{bike\_sharing}, and from LogNormal to Normal NGBoost on \texttt{concrete\_strength}. The rule is vacuous for BDF: all four candidate leaf families returned 9/9 finite CRPS and RMSE on every dataset.

The two substitutions act in opposite directions. The excluded NGBoost LogNormal runs average $2.15\times10^{33}$ CRPS on \texttt{bike\_sharing} and $2.19\times10^{60}$ on \texttt{concrete\_strength} over the folds they did complete, against $21.36$ and $2.32$ for the substituted Poisson and Normal candidates; the \texttt{concrete\_strength} run is also the one recording a negative tuning CRPS ($-7.80\times10^{57}$), so its invalid objective and its divergent evaluation scores are one numerical failure rather than two separate anomalies. The excluded XGBoostLSS Gaussian run on \texttt{yacht\_hydrodynamics} is the opposite case: it averages $0.282$ CRPS over its eight completed folds against $5.914$ for the substituted Laplace candidate, and restoring it would move XGBoostLSS's average relative CRPS from $3.323$ to approximately $1.67$, leaving the ordering of BDF-Full, conformalized LightGBM, and CatBoost-UQ in Table~\ref{tab:rel-to-best-crps} unchanged. These aggregates compare numerically complete variants, rather than the reliability of a family chosen solely on tuning data. Finite poor evaluation scores, including the catastrophic Exponential NGBoost result, remain in the comparison, and the raw artifacts of the excluded runs are retained.

An audit of the locked real-data artifacts found complete reported folds for all included BDF, QRF, DRF, conformalized forest/boosting, CatBoost-UQ, Gaussian deep-ensemble, Bayesian-ridge, $k$NN-KDE, and classification result files. The incomplete XGBoostLSS and NGBoost candidates are listed above. The Gaussian-process~\citep{williams2006gaussian} artifact returns no finite CRPS folds on 7 of the 11 datasets attempted and is retained for transparency but not consumed by any aggregate.

The repository also contains a PyMC-BART~\citep{chipman2010bart} run over all 15 datasets. We do not report it: to keep the sweep tractable each fit used a single chain with 500 draws, which gives no between-chain convergence diagnostic, so the posterior is not resolved enough to attribute the resulting numbers to BART. A multi-chain comparison at this scale is left to future work. The final regression aggregate includes BDF, QRF, DRF, fused XGBoostLSS, fused NGBoost, conformalized LightGBM/RF, CatBoost-UQ, Gaussian deep ensembles, Bayesian ridge, and $k$NN-KDE, plus a climatological reference for CRPSS normalization. The final classification aggregate includes BDF, RF, LightGBM, NGBoost, calibrated RF, calibrated LightGBM, and $k$NN.

For BDF configs that expose split-score selection, the benchmark uses a single effective categorical \texttt{score\_regime}. The regimes expand as \texttt{nle} $\mapsto$ \texttt{score\_method=nle, score\_correction=None}, \texttt{nll\_bic} $\mapsto$ \texttt{score\_method=nll, score\_correction=bic}, and \texttt{nll} $\mapsto$ \texttt{score\_method=nll, score\_correction=None}. This expansion is applied before model construction and result YAMLs store the expanded fields for compatibility with the table and plotting scripts. TPE tunes the score regime jointly with the other hyperparameters. Fixed-regime tables compare separately tuned configurations; the matched-hyperparameter and factorial studies isolate score changes; Normal--Normal has access to \texttt{nle} because it is conjugate, whereas Student-$t$ has only \texttt{nll} and \texttt{nll\_bic}. Selection-frequency counts in the paper are descriptive outcomes of this pre-specified fold-0 tuning split, not estimates of selection probabilities across repeated tuning splits.

The synthetic DGP study uses the same ten-fold convention: fold 0 selects hyperparameters and folds 1--9 report evaluation metrics. BDF core variants are run in the default environment; QRF and DRF are run in the benchmark environment and merged as incremental result shards. DRF is evaluated through the same isolated R worker used in the real-data benchmark, and the final synthetic plots include only shards with aggregate metrics for all evaluation folds.

\subsection{Preprocessing and Dataset Inventory}\label{app:dataset-inventory}
Table~\ref{tab:dataset-inventory} lists the processed benchmark datasets with their task, target domain, and dimensions. Datasets are processed by the repository scripts into numeric design matrices. Numeric columns are used directly, categorical columns are one-hot encoded, and rows with unresolved missing values are dropped during processing; the processed metadata records the number of samples before and after this step. Native categorical handling is not used, even for models that could support it, so all methods receive the same feature matrix. This controlled-input protocol prioritizes like-for-like comparison across methods; production deployments of CatBoost or LightGBM may additionally exploit native categorical splits. Regression targets are standardized inside each training fold for methods that require standardized targets and predictions are inverse-transformed before scoring; classification labels are encoded as binary targets with probabilities reported for the positive class.

Target-domain labels are used to filter incompatible leaf families before fitting, but the real-valued Normal and Student-$t$ leaves remain real-valued predictive distributions even when a processed regression target is positive or count-valued. Their samples, densities, CRPS, central intervals, coverage, PIT values, and interval scores are therefore evaluated on the original target scale without truncating or renormalizing mass outside the natural support. Domain-constrained leaves such as Gamma--Poisson and Gamma--Exponential are included only for compatible target domains; if tuning selects a real-valued leaf on a positive/count dataset, the reported score reflects that explicit modeling choice rather than a support-corrected density.

\subsection{Metric Implementation Details}\label{app:computational-setup-regression-metrics}\label{app:computational-setup-classification-metrics}

The real-data regression ranking uses CRPS \citep{gneiting2007strictly} as the primary probabilistic score,
\[
    \mathrm{CRPS}(F,y)=\int_{-\infty}^{\infty}\left(F(z)-\mathbf{1}\{y\le z\}\right)^2 dz.
\]
When a model exposes analytic quantiles or CDFs we use those outputs directly; when it exposes only predictive samples, the evaluation draws \texttt{sample\_size}=1000 samples and computes CRPS, PIT values, central intervals, empirical coverage, and interval scores from the pooled predictive samples. The central $(1-\alpha)$ interval score \citep{gneiting2007strictly} is
\[
    (u-l) + \frac{2}{\alpha}(l-y)\mathbf{1}\{y<l\}
    + \frac{2}{\alpha}(y-u)\mathbf{1}\{y>u\}.
\]
CRPSS uses the climatological reference model as the denominator, while relative-score tables normalize each method by the best complete method within the table's stated comparison set.

For binary classification, log-loss, Brier score, ECE, AUROC, and AUPRC are computed from predicted probabilities for the positive class. ECE uses ten uniform probability bins on $[0,1]$ and weights each occupied bin by its empirical sample fraction. Reliability diagrams aggregate fold-level calibration curves with the stored bin counts, i.e.\ each bin's plotted point is the count-weighted average over folds and datasets. Because the benchmark datasets differ in class balance and bin occupancy, this aggregate can average out opposing per-dataset miscalibrations; the per-dataset ECE values entering the summary tables are computed before any cross-dataset aggregation and are the quantity used for method comparison.
